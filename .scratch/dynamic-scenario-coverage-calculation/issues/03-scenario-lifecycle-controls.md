# 03 — 实现场景列生命周期操作

**What to build:** 让用户能够在最终参数矩阵中新增、删除和重命名场景，同时保持每个场景的输入和结果独立，空场景状态仍然可以重新新增场景。

**Blocked by:** 02 — 重构输入/输出参数矩阵

**Status:** ready-for-agent

- [ ] 每个场景标题只显示场景名称和始终可见的小型删除按钮，不显示频率、距离等副标题。
- [ ] 单击场景名称继续执行表格选列；点击标题旁的删除按钮立即删除对应场景，不弹确认框、不提供撤销。
- [ ] 允许删除任意场景，包括最后一个场景；删除后其他场景的输入、结果和稳定 ID 不受影响。
- [ ] 场景集合为空时不显示场景结果，但仍在第一个可用场景位置保留新增入口。
- [ ] 场景列集合右侧显示新增入口；点击后创建名称为“新场景”的新场景。
- [ ] 新场景使用固定默认模板：自由空间路损模型、2.4 GHz、100.1 dB 总路损值和基准链路默认输入，不复制当前或其他场景。
- [ ] 双击场景名称后在原位置显示单行输入框；回车或失焦保存，Esc 取消；空名称恢复原名称，允许重名。
- [ ] 新增、删除和重命名通过场景矩阵接缝完成，不以 Tabulator 的列定义作为场景状态来源。
- [ ] 覆盖场景生命周期、空场景重建、名称编辑提交/取消、重名、列选择和场景独立性的用户可观察行为测试。
