# 动态场景与覆盖距离计算

Status: ready-for-agent

## Problem Statement

当前链路预算页面主要是静态参数矩阵，场景列、表格行和展示结果之间缺少明确的领域边界。用户需要为每个场景独立填写链路预算输入，并根据所选路损模型和路损值自动得到覆盖距离；同时还需要能够增删场景、重命名场景，并继续使用类似 Excel 的选区、复制和粘贴操作。

当前界面还有几项会妨碍后续扩展的问题：

- 场景列不能动态增加、删除或重命名。
- 路损模型、路损值和覆盖距离没有形成明确的输入/输出关系。
- 表格分组占用数据行，参数名称、单位、场景输入和计算结果的职责混在一起。
- 计算结果如果作为普通单元格处理，可能被用户编辑或 Excel 粘贴覆盖。
- 现有 Tabulator 组件同时承担场景状态、参数定义、计算展示和剪贴板逻辑，后续增加模型和计算结果会越来越难维护。

## Solution

将页面改造成以场景为中心的链路预算矩阵：

- 每个场景占一列，场景输入完全独立。
- 表格内只有最左侧参数名称列固定；单位并入参数名称，例如“载波频率（GHz）”。
- 分组名称放在表格左侧独立的固定分组栏，不占用参数数据行。
- 场景列顶部只显示场景名称和始终可见的小型删除按钮，不显示副标题。
- 场景名称双击后在原位置编辑。
- 输入参数位于表格上部，底部单独显示只读计算结果。
- 第一版提供自由空间路损模型：用户输入路损模型、载波频率和总路损值，计算覆盖距离。
- 页面首次加载、输入提交和整块粘贴完成后自动计算；错误显示在对应结果单元格，并标记相关输入。
- 计算引擎与 Vue、Tabulator 解耦，场景状态只保存输入，覆盖距离等结果由模型派生。
- 通过固定的场景矩阵应用接缝承接增删、重命名、输入更新、批量粘贴和计算结果，Tabulator 只负责表格交互适配。

## User Stories

1. 作为链路预算用户，我希望每个场景以独立列显示，以便并排比较不同链路配置。
2. 作为链路预算用户，我希望每个场景拥有独立的路损模型、模型参数和其他输入，以便修改一个场景时不影响其他场景。
3. 作为链路预算用户，我希望在场景名称旁看到一个小型删除按钮，以便直接删除不需要的场景。
4. 作为链路预算用户，我希望点击删除按钮后立即删除对应场景，不被确认对话框打断。
5. 作为链路预算用户，我希望最后一个场景也能被删除，以便回到没有场景结果的空状态。
6. 作为链路预算用户，我希望所有场景删除后仍能看到新增入口，以便从空状态重新建立场景。
7. 作为链路预算用户，我希望点击新增入口创建一个使用固定默认值的新场景，以便快速开始配置。
8. 作为链路预算用户，我希望新增场景不复制当前场景，以便不同场景的输入边界清晰可控。
9. 作为链路预算用户，我希望新增场景默认名称为“新场景”，以便立即识别新建列。
10. 作为链路预算用户，我希望双击场景名称后在原位置编辑，以便不离开矩阵上下文。
11. 作为链路预算用户，我希望按回车或点击其他位置保存场景名称，以便使用自然的表格编辑习惯。
12. 作为链路预算用户，我希望按 Esc 取消场景名称编辑，以便恢复原名称。
13. 作为链路预算用户，我希望空名称不会覆盖原名称，以便每个场景始终有可识别的标签。
14. 作为链路预算用户，我希望不同场景允许使用相同名称，以便名称只作为显示标签而不是身份标识。
15. 作为链路预算用户，我希望单击场景名称仍然可以选中整列，以便继续使用 Excel 式复制操作。
16. 作为链路预算用户，我希望场景列较多时可以横向滚动，以便名称和参数值保持可读。
17. 作为链路预算用户，我希望横向滚动时始终看到分组名称和参数名称，以便不丢失当前单元格的语义。
18. 作为链路预算用户，我希望参数名称是唯一固定的表格结构列，以便知道每个输入值对应哪个参数。
19. 作为链路预算用户，我希望单位直接显示在参数名称中，以便每个参数只占用一行。
20. 作为链路预算用户，我希望分组名称显示在表格左侧并垂直对应参数区域，以便分组不会挤占数据行。
21. 作为链路预算用户，我希望分组之间使用统一浅色背景和较粗分隔线，以便看到结构层次而不抢过数据重点。
22. 作为链路预算用户，我希望输入参数全部位于计算结果上方，以便清楚区分输入和输出。
23. 作为链路预算用户，我希望底部有独立的计算结果区域，以便覆盖距离和未来其他结果不会被误认为输入。
24. 作为链路预算用户，我希望选择路损模型时使用下拉框，以便避免输入无法识别的模型文字。
25. 作为链路预算用户，我希望第一版可以选择自由空间路损模型，以便先完成最小可用计算流程。
26. 作为链路预算用户，我希望填写路损值作为模型使用的总路损值，以便覆盖距离计算有明确的工程语义。
27. 作为链路预算用户，我希望路损值为空时得到明确的缺少输入诊断，以便知道还需要填写什么。
28. 作为链路预算用户，我希望非空路损值必须大于 0，以便拒绝无效的路损输入。
29. 作为链路预算用户，我希望载波频率必须大于 0，以便自由空间模型能够进行有效反解。

31. 作为链路预算用户，我希望页面初次打开时就能看到默认场景的覆盖距离，以便无需先修改参数才能判断页面是否工作。
32. 作为链路预算用户，我希望输入单元格提交后立即重新计算对应场景，以便修改结果无需额外点击“计算”按钮。
33. 作为链路预算用户，我希望输入框正在编辑时不因每个字符触发计算，以便避免临时输入状态产生闪烁错误。
34. 作为链路预算用户，我希望修改任意场景输入都会触发该场景重算，以便将来接入更多模型参数时不需要重新设计更新机制。
35. 作为链路预算用户，我希望当前模型暂时不使用的其他链路预算参数仍可编辑，以便为后续完整链路预算保留输入入口。

43. 作为链路预算用户，我希望输入值先按原始文本保留，以便第一版不因自动格式化改变我的输入。
44. 作为链路预算用户，我希望具体路损模型负责解析、校验和解释自身错误，以便错误信息符合模型领域规则。
45. 作为链路预算用户，我希望一次粘贴多个单元格后整块数据写入完成再计算，以便避免逐格刷新。
46. 作为链路预算用户，我希望 Excel 粘贴的起始选中单元格必须是可编辑输入单元格，以便不会从固定参数名称或只读结果位置开始写入。

## Implementation Decisions

- 以场景矩阵应用服务作为功能边界。它维护有序的场景集合，处理新增、删除、重命名、输入更新和批量粘贴，并返回包含输入、派生结果和诊断状态的场景矩阵视图模型。
- 场景使用稳定且独立于显示名称的 ID。名称允许重复，重命名不改变 ID；删除只影响目标场景。
- 场景输入按场景独立保存。第一版新增场景使用固定默认模板，不复制其他场景。
- 第一版默认模板为：自由空间路损模型、2.4 GHz、100.1 dB 总路损值、名称“新场景”、其他保留输入使用基准链路默认值。覆盖距离由计算引擎得到约 1 km。
- 表格投影只有一个固定的参数名称列。单位作为参数名称的显示元数据，不再投影为表格列。
- 分组栏是位于表格左侧的独立展示区域，不属于可编辑矩阵；分组不再使用占用数据行的分组标题行。参数名称列和分组栏在场景横向滚动时固定。
- 当前原型保留现有链路预算输入集合，新增路损模型和路损值，使用覆盖距离替代原链路距离输出，移除环境附加损耗和静态评估。原型阶段沿用现有输入分组名称；结果独立位于底部“计算结果”区域，正式设计时可统一调整名称。
- 场景标题只显示名称和小型、始终可见的删除按钮，不显示频率或距离副标题。标题单击保留列选中行为，标题双击进入原位文本编辑。
- 删除按钮立即删除场景，不弹确认框，不提供撤销；允许删除最后一个场景。新增按钮位于场景列集合右侧，空场景时位于第一个可用场景列位置。
- 输入单元格单击用于选择，双击进入统一文本编辑器；回车或失焦提交，Esc 取消。空值允许保存，但计算层应返回缺少输入的诊断。
- 路损模型输入使用选择控件，第一版只注册自由空间路损模型。路损值表示总路损，非空时必须大于 0；载波频率必须大于 0。
- 自由空间模型使用 GHz、dB 和 km 的界面单位，根据载波频率和总路损值反解覆盖距离。环境附加损耗不属于第一版模型输入；其他保留的链路预算参数保持可编辑，但当前自由空间模型可以不使用它们。
- 覆盖距离是派生结果，不写回可编辑输入状态。初次加载时计算默认输入；输入提交后重新计算对应场景；整块 Excel 粘贴完成后，对受影响场景各计算一次。
- 计算结果统一显示在底部结果区域。第一版覆盖距离显示两位小数并只读；后续模型可增加更多只读结果行。
- 通用输入层只负责保留原始文本和基础输入边界，具体路损模型负责解析、领域校验、正向计算、路损反解和结构化诊断。模型诊断包含足以定位字段的上下文，界面将其映射为简短提示并标记相关输入。
- 无效输入或模型无法计算时，结果单元格显示诊断信息，不保留旧结果；其他场景仍独立计算。
- Tabulator 仅作为表格适配层，负责列投影、选择、双击编辑、表头按钮和 DOM 事件桥接；场景生命周期和计算规则不应依赖 Tabulator 内部数据结构。
- 剪贴板适配器继续使用纯文本 Tab/换行格式。复制可以包含固定参数名称列和只读结果，但不包含左侧分组栏；复制场景标题时使用最新名称。
- 粘贴必须从可编辑场景输入单元格开始；不自动识别表头；合法范围内跳过只读参数名称或结果位置，忽略超出范围的数据；写入整块数据后统一触发受影响场景的计算。
- 计算结果和场景输入在状态模型中分离。只读结果可复制但不能通过粘贴修改；刷新恢复默认内容，第一版不做内容持久化。
- 为后续扩展保留模型注册表和模型元数据能力。模型可以声明所需输入、默认值、分组、正向路损计算、路损反解和结果定义；后续模型可动态增加或隐藏参数行并扩展结果行。

## Testing Decisions

- 测试以外部可观察行为为准，不测试 Tabulator 的内部实现、具体 DOM 层级或内部状态字段。
- 主测试接缝为“场景矩阵状态 → 用户操作 → 下一版场景矩阵状态”。通过该接缝覆盖场景生命周期、输入编辑、剪贴板写入、自动计算、只读结果和诊断状态。
- 场景矩阵应用服务需要覆盖：初始化默认场景、新增默认场景、删除任意场景、删除最后一个场景、空场景新增、名称双击编辑的提交与取消、重名场景和场景独立性。
- 计算行为需要覆盖：页面初始化计算、路损模型选择、频率变化、总路损变化、路损值为空、路损值为零或负数、频率非正、其他暂未使用输入变化、有效结果替换旧结果以及单场景错误不影响其他场景。
- 自由空间模型需要通过功能契约验证正向关系和反解结果的一致性，并验证 GHz、dB、km 单位下默认值约得到 1 km。
- 剪贴板行为需要覆盖：合法可编辑起点、固定参数名称起点被拒绝、只读覆盖距离可复制但不能被写入、粘贴范围跳过只读位置、超出范围忽略、不识别表头、整块粘贴后只计算一次受影响场景。
- 结果投影需要覆盖：覆盖距离只读、显示两位小数、错误诊断替换旧结果、相关输入错误标记、复制结果到 Excel 以及场景名称更新后复制表头。
- 表格适配层只需要少量用户级冒烟测试，验证场景标题的单击选列、双击原位编辑、删除按钮、空场景新增按钮和横向滚动下固定区域可用；不对 Tabulator 的具体实现细节建立测试依赖。
- 当前代码库没有既有测试框架或同类测试可复用；实现时应补充能够运行上述主接缝测试的测试基础设施，但测试断言仍保持在用户可观察行为层。

## Out of Scope

- 根据速率需求、带宽、调制编码、噪声系数等参数计算最大允许路损。
- 完整链路预算方程、接收功率、链路余量自动推导和工程级性能评估。
- 环境附加损耗在自由空间模型中的计算；第一版不保留该输入行。
- 除自由空间路损模型以外的具体模型实现。
- 用户输入任意公式文本并直接执行。
- 场景输入或结果的持久化、后端同步、导入导出文件和撤销恢复。
- 参数行的新增、删除或用户自定义参数；模型驱动的动态参数行只保留扩展接口，不要求第一版实现具体新增模型。
- 重新设计所有正式参数名称、分组名称和完整产品视觉语言；本规格只固定原型阶段的结构行为。
- 改变既有报告布局为其他页面布局。

## Further Notes

- 规格中的“路损值”是第一版自由空间反解使用的总路损值，不是单独的自由空间分量。
- “覆盖距离”始终是计算结果，不是用户输入；用户可以复制它，但不能通过编辑或粘贴覆盖它。
- 其他保留参数当前可以不影响自由空间结果。计算协调器仍应在这些输入提交后重新计算，以便未来模型接管它们。
- 模型诊断应保持结构化，界面文案只是诊断的展示映射；不要把领域判断写成通用表格校验。
- 该规格记录的是当前原型阶段的实现边界。后续正式设计可统一调整参数名、分组名和结果布局，但不应破坏场景独立性、输入/结果分离和模型扩展接缝。
